FASE DI DEPLOY — La Sorgente (Hub Operativo Bandi AI)
======================================================
Ultimo aggiornamento: 2026-05-21

Questo documento riassume i passaggi operativi per consegnare il progetto "La Sorgente" al cliente o per caricarlo online in ambiente di produzione.


1. PULIRE IL PACKAGE E CREARE LO ZIP
-------------------------------------
Per semplificare la consegna o il caricamento, abbiamo inserito uno script Python che effettua la pulizia e il packaging automatico escludendo cartelle pesanti (`venv/`), file segreti (`.env`) o file temporanei di test (`uploads/`, `.DS_Store`):

Esegui semplicemente nel terminale:
  python crea_pacchetto.py

Questo genererà un file pulito chiamato "la_sorgente_deploy.zip" pronto per essere consegnato o caricato sul server.


2. DATABASE.JSON — COSA FARE
-----------------------------
Il file database.json contiene già i dati reali di La Sorgente:
  - Profilo associazione compilato (APS, Cagliari, RUNTS, budget 45.000€)
  - 5 bandi già caricati
  - 1 bozza progetto generata
  - 2 documenti caricati

OPZIONE A (consigliata): consegnarlo com'è → il cliente parte con tutto già popolato.
OPZIONE B: azzerarlo → il cliente ricomincia da zero compilando il profilo dalla UI.


3. API KEY GEMINI PER IL CLIENTE
----------------------------------
Il cliente ha bisogno di una propria chiave API gratuita di Google Gemini.

Istruzioni da dare al cliente:
  1. Andare su https://aistudio.google.com
  2. Accedere con un account Google
  3. Cliccare "Get API Key" → "Create API key"
  4. Copiare la chiave generata
  5. Incollarla nel file .env nella riga: GEMINI_API_KEY=la_chiave_qui

Il tier gratuito di Gemini 2.5 Flash è ampiamente sufficiente per l'utilizzo normale dell'app.


4. FILE .ENV DA CREARE PER IL CLIENTE
---------------------------------------
Creare un file chiamato ".env" nella cartella del progetto con questo contenuto:

  GEMINI_API_KEY=inserisci_qui_la_tua_chiave_gemini
  APP_PASSWORD=password_segreta_qui_se_deploy_remoto
  PERSISTENT_DATA_DIR=cartella_per_dati_persistenti_se_deploy_remoto

Note sul file .env:
- Non includere virgolette attorno alle chiavi o alle password.
- Se APP_PASSWORD viene omessa o lasciata vuota, l'applicazione funzionerà in modalità "Accesso Libero" (ideale per sviluppo offline o uso locale).
- Se APP_PASSWORD viene impostata, l'intera piattaforma richiederà l'inserimento della password per l'accesso (Password Gate con stile glassmorphic).
- PERSISTENT_DATA_DIR: Consente di salvare i database e i documenti caricati in una cartella persistente sicura (es. su un disco montato in cloud come /data), evitando perdite di dati a seguito di riavvii dei server. Riferiti a "guida_deploy.md" per i dettagli.


5. GUIDA AL DEPLOY DETTAGLIATA (NEW)
-------------------------------------
Per tutti i dettagli tecnici su come mettere online l'applicazione, fare riferimento al file dedicato:
  => "guida_deploy.md" (presente nella cartella radice)

La guida copre nel dettaglio:
  - Deploy consigliato su Google Cloud Run con Cloud Storage FUSE (Firebase-ready, free tier)
  - Deploy su Render.com usando "render.yaml" (Blueprint)
  - Deploy universale tramite container con "Dockerfile"
  - Deploy tradizionale su VPS Linux con Systemd, Nginx, HTTPS ed SSL gratuito (Let's Encrypt / Certbot)


6. STATO DEI PROBLEMI NOTI (RISOLTI)
-------------------------------------
a) Riconoscimento Dinamico dell'Ente: RISOLTO ✓
   Il nome dell'associazione viene estratto in tempo reale dal database. Se il nome cambia nella UI, tutti i prompt a Gemini si aggiornano all'istante.

b) Protezione e Password Gate Centrale: RISOLTO ✓
   Se APP_PASSWORD è definita in `.env`, l'intera app viene protetta dietro a una bellissima schermata di login con stile glassmorphic e cookie di sessione validi 30 giorni.

c) Resilienza Cloud e Dati Persistenti: RISOLTO ✓
   Aggiunto il supporto alla cartella `/data` persistente (tramite PERSISTENT_DATA_DIR) per azzerare il rischio di perdita dati su macchine ephemeral come Render.com.
